# Руководство по поиску в разных типах файлов

Цель этого руководства - описать инструменты для поиска и его упрощения относительно большинства популярных типов файлов и баз данных.
В большей степени руководство применимо к поиску в утечках разных сайтов (большие текстовые файлы в архивах, csv/sql), документах (pdf, xls(x), doc(x))
и в специализированных базах (1С, Cronos и т.д.).

## Универсальный поиск

### Datashare

[Datashare](https://datashare.icij.org/) - кросс-платформенное решение от ICIJ, предназначенное для совместной работы с большими наборами документов, в первую очередь среди исследователей и журналистов.

Позволяет искать по PDF, изображениям, текстовым файлам, таблицам, презентациям и многим другим форматам.

![image](https://datashare.icij.org/assets/Demo_LightMode-DQAYqzvC.png)

### dnGrep

[dnGrep](http://dngrep.github.io/) - универсальная утилита с графическим интерфейсом для Windows, умеет искать в текстовых файлах, документах,
PDF и во всех популярных форматах архивов. Поддерживается поиск по регулярному выражению и по всем файлам в директории, есть интеграция с Проводником.

Несмотря на некоторые неудобства с подсветкой результатов и сбои применительно к большим архивам, выглядит одной из самых перспективных для массового поиска
в файлах с текстовым содержимым.

![image](https://github.com/dnGrep/dnGrep/wiki/Images/grep-main.png)

### AstroGrep

[AstroGrep](https://astrogrep.sourceforge.net/) - утилита с графическим интерфейсом для Windows, позволяющая искать текст сразу по множеству файлов, что особенно удобно при работе с большими наборами документов. Поддерживает различные форматы файлов и имеет удобный пользовательский интерфейс.

Главные преимущества AstroGrep - быстрый текстовый поиск по большим объёмам файлов и подсветка найденных совпадений прямо в содержимом файла, что упрощает просмотр результатов. Также есть поддержка регулярных выражений для более сложных и точных запросов.

При этом AstroGrep ориентирован именно на текстовый поиск, поэтому не работает с Excel-документами, архивами, изображениями и аудио.

![image](https://astrogrep.sourceforge.net/pics/ss_main_new.png)

### Pinpoint

[Google Pinpoint](https://journaliststudio.google.com/pinpoint/about/) - облачный инструмент, разработанный для помощи журналистам в работе с большими объёмами информации.
Поддерживает разные типы файлов, включая документы (почти всё конвертируется в PDF), изображения и аудио, а также интегрируется с Google Drive для удобного управления данными. Существенно повышает скорость работы за счёт быстрого поиска по обширным наборам данных.

Среди преимуществ Pinpoint - продвинутые поисковые возможности, которые экономят время при просмотре данных, и поддержка совместной работы: над одним проектом может одновременно работать несколько пользователей.

![image](https://storage.googleapis.com/support-kms-prod/dBrMUtT6Ywj9XltPawwCMGkvjfVyQIaJ7zwX)

## Текстовые файлы

### grep

Эталон отрасли для поиска в текстовых файлах - это unix-утилита `grep`. Вы указываете при её запуске два параметра: шаблон для поиска и файл;
после чего утилита выводит строки, совпавшие с шаблоном. В простейшем случае шаблоном является некая строка, которую мы хотим найти в файле
(например, номер телефона или почтовый ящик).

На базе `grep` также построены другие утилиты, так что запомним основные параметры для запуска:

`-A number` - вывод некоторого количества строк после (`after`) найденной: полезно, если дополнительные сведения хранятся в файле после нашей строки

`-B number` - вывод некоторого количества строк до (`before`) найденной: полезно, если дополнительные сведения хранятся в файле до нашей строки

`-С number` - вывод некоторого количества строк до и после найденной

`-i` - регистронезависимый поиск, только при этом режиме поиск по `Target` и `target` найдёт строку "TARGET"

`-R` - рекурсивный поиск, в этом режиме утилита сможет искать во всех вложенных директориях (для поиска по любым файлам в текущей достаточно указать * вместо названия файла)

`-a` - воспринимать все файлы как текстовые, использовать при ошибке `Двоичный файл (стандартный ввод) совпадает`

Пример поиска через `grep`:

`grep -iR target dumps/*` - будет произведён поиск по слову `target` во всех регистрах во всех текстовых файлах в директории `dumps`

### ripgrep

[ripgrep](https://github.com/BurntSushi/ripgrep) (`rg`) - современная альтернатива `grep`, написанная на Rust. Существенно быстрее на больших директориях, по умолчанию работает рекурсивно и поддерживает большую часть параметров `grep`. По умолчанию `ripgrep` пропускает скрытые, бинарные и перечисленные в `.gitignore` файлы, что часто неудобно при работе с утечками и дампами - в таких случаях помогает флаг `-uu`, отключающий все фильтры.

Основные параметры аналогичны `grep`:

`-A number` - вывод некоторого количества строк после найденной

`-B number` - вывод некоторого количества строк до найденной

`-C number` - вывод некоторого количества строк до и после найденной

`-i` - регистронезависимый поиск

`-a` - воспринимать бинарные файлы как текстовые

`-uu` - отключить все фильтры по умолчанию (искать в скрытых, бинарных и gitignore-файлах)

`-t type` - искать только в файлах определённого типа (например, `-t csv`, `-t sql`)

Пример поиска через `ripgrep`:

`rg -i -uu target dumps/` - рекурсивный регистронезависимый поиск слова `target` по всем файлам в директории `dumps`, включая скрытые и попавшие в gitignore

## Исходный код

### The Silver Searcher

[The Silver Searcher](https://github.com/ggreer/the_silver_searcher) (`ag`) - утилита для поиска, оптимизированная под исходный код. Быстрее, чем `grep` и `ack`, по умолчанию игнорирует файлы из `.gitignore`/`.hgignore`, пропускает скрытые файлы и бинарные блобы. Удобно использовать, когда нужно найти имя символа, утёкший API-ключ или строку с учётными данными в клоне репозитория.

Пример использования `ag`:

`ag -i 'api_key' src/` - регистронезависимый поиск `api_key` по дереву исходников `src/`

Более широкий каталог grep-подобных утилит (включая специализированные для PDF, архивов, сетевого трафика, облачных хранилищ и истории браузера) собран в подборке [awesome-grep](https://github.com/cipher387/awesome-grep).

## Регулярные выражения

Обычной строки достаточно, чтобы найти конкретное имя или номер телефона, но если нужно вытащить из файла *все* email-адреса, телефоны, номера банковских карт, URL или IP-адреса - на помощь приходят регулярные выражения. И `grep -E`, и `ripgrep` их поддерживают.

### grep_for_osint

[grep_for_osint](https://github.com/cipher387/grep_for_osint) - набор готовых shell-скриптов, которые с помощью `grep` и регулярных выражений извлекают из файла или директории типовые OSINT-артефакты: email-адреса, телефоны, номера банковских карт, URL, IP-адреса, никнеймы и произвольные ключевые слова. Результаты пишутся в текстовые файлы с временной меткой, что удобно при обработке больших дампов и архивов Wayback Machine.

## Документы

### xlsxgrep

Для поиска в документах XLSX можно использовать либо `grep`, предварительно сконвертировав таблицу в CSV, либо использовать утилиту
`xlsxgrep`. Пример поиска:

`xlsxgrep target -H -N -r dumps/*`

### zgrep

Для поиска в архивах .gz, .tgz можно использовать утилиту `zgrep`.

Использование аналогично обычному `grep`, за исключением следующих особенностей:
- режим рекурсивного поиска `-R` не поддерживается
- наряду с архивами утилита также может искать по текстовым файлам

Пример поиска через `zgrep`:

`zgrep -ia target dumps/*` - будет произведён поиск по слову `target` во всех регистрах во всех текстовых файлах и gz-архивах в директории `dumps`

### 7zip

Для поиска в архивах `7zip` можно использовать соответствующую утилиту для полной распаковки в цепочке с `grep`:

Пример использования:

`7z x archive.7z -so | grep ...`

`7zip` также умеет работать со многими другими типами архивов.

### unrar

Для поиска в архивах `rar` можно использовать соответствующую утилиту для полной распаковки в цепочке с `grep`:

Пример использования:

`unrar p archive.rar | grep ...`

## Базы данных

### SQL-дампы

Дампы баз данных в формате `.sql` - обычный текст, поэтому `grep` и `ripgrep` работают по ним напрямую, и это, как правило, самый быстрый способ найти в утёкшем дампе конкретное значение. Для изучения структуры большого дампа (таблицы, столбцы, связи) удобнее импортировать его в локальный MySQL/MariaDB/PostgreSQL и работать с ним через десктопный клиент.

Рекомендуемые кросс-платформенные клиенты:

- [DBeaver](https://dbeaver.io/) (Community Edition) - бесплатный, open-source, поддерживает MySQL/MariaDB/PostgreSQL/SQLite/MS SQL/Oracle и десятки других СУБД. Есть SQL-редактор с автодополнением, ER-диаграммы по схеме, быстрый просмотрщик таблиц на миллионы строк и импорт/экспорт CSV.
- [Beekeeper Studio](https://www.beekeeperstudio.io/) - open-source клиент с более лёгким и современным интерфейсом. Хорошая альтернатива, если DBeaver кажется тяжеловесным.

### cronodump

Для популярного в России формата баз данных Cronos следует использовать либо соответствующую версию клиента (Cronos, CronosPlus, CronosPro)
либо можно сконвертировать базу в формат таблицы CSV с помощью утилиты [cronodump](https://github.com/alephdata/cronodump):

```
git clone https://github.com/alephdata/cronodump && cd cronodump
python3 setup.py install
croconvert --csv cronos_db_directory/

# будет создана новая директория c файлами
ls cronodump-2022-04-25-02-53-57-293000
БТК.csv  Files-FL

grep ...
```

### 1C

Для анализа файлов баз данных 1C можно использовать библиотеку [onec_dtools](https://github.com/Infactum/onec_dtools) или готовую утилиту [1c-database-converter](https://github.com/soxoj/1c-database-converter), способную вытащить все текстовые строки и бинарные данные из базы любого формата.

```
./run.py 8-2-14.1CD
Target: 8-2-14.1CD
Results found: 1
1) Out Dir: 8-2-14.1CD_csv
File Type: 1CD
Status: Exported content of 1CD file

------------------------------
Total found: 1
```
